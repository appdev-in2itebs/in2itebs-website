#### Important (Should Fix)

1. **Runbook statements are now false or misleading.** `docs/REMEDIATION_RUNBOOK.md:56` still says "No Git repository or remote has been created" (H3 is half-closed: repository yes, remote no). `:21` says `/api/health/` returns "the build's `siteEnv`" but `web/app/api/health/route.ts:8` reports the *runtime* process value, which is exactly the build/start skew the same document warns about at `:17`. `:49` says `npm run check` runs "lint, type checking and server/unit tests" (it now runs `format:check` first) and that `test:browser` "expects the running built website on 3107" (Playwright now starts one when none is listening). Fix: three sentence edits; the health line should say "the `SITE_ENV` of the running process, which must equal the value the build was made with".
2. **Case-study summary misattributes the engagement.** `web/content/case-studies.ts:278-279`: "Andhra Pradesh Power Transmission Corporation ran a three-year onsite AMS engagement" contradicts the scenario ("engaged In2IT EBS for a three-year onsite application-management engagement"). This is the `<meta name="description">` of a named client page. Fix: "Andhra Pradesh Power Transmission Corporation engaged In2IT EBS for a three-year onsite AMS engagement that kept a critical ERP backbone stable." (143 characters, within the 155 test bound).
3. **Process ceiling is consumed before the per-address tier rejects.** `web/lib/lead-service.ts:81-86` increments the 120/min process bucket first, so behind a trusted proxy one abusive address can 429 the whole instance for a minute with requests the address tier would have refused at 10. This is a plan-text defect the ledger accepted as residual; the fix is a two-line reorder (address tier, then process tier) after which a single address contributes at most 10/min to the process bucket. Untrusted deployments are unchanged (no address tier).
4. **`X-Forwarded-For` leftmost-value trust needs a stronger operator warning.** `web/lib/lead-service.ts:83-84` takes `split(",")[0]`. The runbook (`:35`) says "Sucuri or any ingress that overwrites `X-Forwarded-For`", but Cloudflare (the tunnel currently used for preview) *appends* the connecting IP, so an operator who enables the flag behind it makes the per-address limiter spoofable. Not a CSRF bypass (the origin filter does not depend on it), and the email and process tiers still apply, but the failure is silent. Fix: state explicitly in `web/.env.example:7-9` and the runbook that Cloudflare-style ingresses append and are therefore *not* eligible, or add a `TRUSTED_PROXY_HOPS` count and take the value that many entries from the right.
5. **HSTS `includeSubDomains` is a deploy precondition the runbook does not record.** `web/next.config.mjs:33` sends `max-age=63072000; includeSubDomains` on every non-dev build. Once a browser sees it on `in2itebs.com`, every `*.in2itebs.com` host is forced to HTTPS for two years on that browser. The runbook (`:45`) records only the `preload` decision. Fix: add "confirm every in2itebs.com subdomain serves valid TLS before the first production deploy" next to the preload sentence; if that cannot be confirmed, drop `includeSubDomains` until it can.
6. **The 410 path and the 308 destinations have no automated test at the HTTP level.** `web/next.config.mjs:47-49` and `web/app/api/gone/route.ts` were verified only by curl (ledger line 70). The unit test checks the data, not the rewrite. Fix: add to `web/tests/browser/security-headers.spec.ts` (or a small `redirects.spec.ts`) two `request.get(path, {maxRedirects: 0})` assertions: `/case/anything/` -> 410 with `text/html`, `/join-our-team/` -> 308 with `location` ending `/careers/`.

### Recommendations

- Reorder the limiter tiers and make the trusted-hop count explicit (`TRUSTED_PROXY_HOPS`, default 1, rightmost-N selection) so the per-address tier is correct behind both overwriting and appending ingresses.
- Stamp the build-time `SITE_ENV` into the bundle and expose it from `/api/health/`; add "curl the health route and compare `siteEnv` with `buildSiteEnv`" to the deploy checklist.
- Add a deploy note that Next serves prerendered HTML with `Cache-Control: s-maxage=31536000`; the CDN in front of production must be purged on every release or HTML can go stale for a year (verified on the live preview).
- Replace the prerender count floor with an explicit allow-list of dynamic routes.
- Fold `next.config.mjs`, `playwright.config.ts`, `eslint.config.mjs` and the Tailwind/PostCSS configs into the Prettier globs and `scripts/` into ESLint so the style gate is complete.
- Push the branch to the nominated remote before merge so CI runs at least once on a clean runner; the `webServer` cold-start path (`SITE_ENV` via Playwright `env`) has only been exercised locally against an already-running server.
- Once a lead receiver exists, add a browser test for the accepted-lead path (submit, `Set-Cookie ... Secure` on loopback, `/thank-you/` shows the reference); today the suite can only prove the unconfigured branch.
